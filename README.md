# فروشگاه اینترنتی کیان اکسسور

فروشگاه فارسی و راست‌چین برای کمربند، کیف و اکسسوری. Node.js + SQLite، بدون سرویس پولی و بدون CDN خارجی (فونت و آیکون‌ها همراه پروژه‌اند).

## امکانات

**مشتری:** ثبت‌نام/ورود با موبایل و رمز (و اختیاری گوگل) • جست‌وجو، دسته‌بندی، مرتب‌سازی • سبد خرید چندمحصولی • ثبت سفارش با محاسبه قیمت سمت سرور • تاریخچه سفارش‌ها • پیگیری با کد رهگیری (حتی بدون ورود، با کد + موبایل) • لغو سفارش در حالت «در انتظار بررسی» • نصب‌پذیر به‌صورت PWA.

**مدیریت:** داشبورد • سفارش‌ها (جست‌وجو، فیلتر، تغییر وضعیت با یادداشت برای مشتری) • محصولات (قیمت، تخفیف، موجودی، چند تصویر، مخفی/نمایش) • دسته‌ها • کاربران (ارتقا به مدیر/مسدودسازی، فقط مالک) • تنظیمات فروشگاه (تماس، ارسال، متن پرداخت، اعلان) • پشتیبان‌گیری و بازیابی (فقط مالک).

**اعلان سفارش:** تا وقتی پنل مدیریت باز است، با ثبت سفارش جدید پیام و صدا می‌گیرید (بررسی هر ۲۵ ثانیه).

## اجرای محلی

```bash
npm install
cp .env.example .env     # و مقادیر را پر کنید
npm start                # http://localhost:3000
npm test                 # ۳۴ تست یکپارچه روی دیتابیس موقت
```

نیاز: Node.js 20 یا بالاتر. در اولین اجرا حساب مالک ساخته می‌شود (شماره `OWNER_PHONE`). اگر `OWNER_PASSWORD` را نگذاشته باشید، یک رمز تصادفی **فقط یک‌بار** در لاگ سرور چاپ می‌شود. بعد از ورود از «حساب من» رمز را عوض کنید. سپس از `/#/admin` وارد پنل شوید.

## انیمیشن‌ها

GSAP + ScrollTrigger + Lenis به‌صورت خودمیزبان در `public/vendor` هستند (بدون CDN، پس روی شبکه داخلی هم کار می‌کنند) و منطق آن‌ها در `public/fx.js` است: ورود هیرو با حلقه و ذرات نقره‌ای، شیب سه‌بعدی لوگو با ماوس، نوار متحرک، اسکرول نرم، ظاهر شدن تدریجی کارت‌ها و بخش‌ها هنگام اسکرول، افکت نور و بالا آمدن کارت محصول، دکمه‌های مغناطیسی، شمارش آمار در پنل و پرش نشان سبد خرید. اگر کاربر «کاهش حرکت» را در سیستم فعال کرده باشد همه خاموش می‌شوند. برای غیرفعال کردن کامل، تگ‌های `vendor/*` و `fx.js` را از `public/index.html` حذف کنید.

## نسخه نمایشی (Preview) روی GitHub Pages

برای دیدن ظاهر و تجربه فروشگاه بدون سرور، یک نسخه ایستا ساخته می‌شود که API را داخل مرورگر شبیه‌سازی می‌کند (داده‌ها فقط در مرورگر خودتان ذخیره می‌شود و محصولات نمونه‌اند).

```bash
node preview/build.js      # خروجی در پوشه dist/
```

با هر push به شاخه `main`، گیت‌هاب‌اکشنز ابتدا تست‌ها را اجرا می‌کند و اگر سبز بود، Preview را روی Pages منتشر می‌کند. ورود نمایشی: مدیر `09039665868` / مشتری `09121234567` با رمز `demo1234`. این نسخه **هیچ ارتباطی با دیتابیس واقعی ندارد** و برای استفاده عملیاتی نیست.

## متغیرهای محیطی

| نام | توضیح |
|---|---|
| `PORT` | پورت (معمولاً میزبان تعیین می‌کند) |
| `DATA_DIR` | مسیر ذخیره‌ساز **دائمی** برای دیتابیس، تصاویر و پشتیبان‌ها |
| `OWNER_PHONE` / `OWNER_PASSWORD` | حساب مالک اولیه |
| `GOOGLE_CLIENT_ID` | فعال‌سازی ورود با گوگل (اختیاری) |
| `BACKUP_KEEP` | تعداد پشتیبان خودکار (پیش‌فرض ۷) |
| `SQLITE_JOURNAL` | `WAL` (پیش‌فرض) یا `DELETE` اگر فایل‌سیستم میزبان مشکل داشت |

## ورود با گوگل (اختیاری)

1. در Google Cloud Console یک OAuth Client از نوع **Web application** بسازید.
2. در Authorized JavaScript origins آدرس سایت را بگذارید (مثلاً `https://shop.example.com`).
3. Client ID را در `GOOGLE_CLIENT_ID` قرار دهید. دکمه ورود خودکار ظاهر می‌شود. توکن سمت سرور بررسی می‌شود (audience، issuer، انقضا، تأیید ایمیل).

اگر `GOOGLE_CLIENT_ID` خالی باشد، دکمه اصلاً نمایش داده نمی‌شود.

## استقرار روی پافرلند (Node.js)

> جزئیات پنل پافرلند را من نمی‌توانم از اینجا ببینم؛ مراحل زیر الگوی استاندارد میزبان‌های Node.js است. اگر اسم گزینه‌ها فرق داشت، معادلش را انتخاب کنید.

1. محتوای پروژه (بدون `node_modules`) را آپلود کنید یا از گیت بکشید.
2. دستور نصب: `npm install --omit=dev` — دستور اجرا: `npm start` — فایل ورودی: `server.js`.
3. متغیرهای محیطی بخش بالا را در پنل وارد کنید. `PORT` را خود میزبان می‌دهد و برنامه آن را می‌خواند.
4. **مهم:** `DATA_DIR` را روی مسیر ذخیره‌ساز دائمی بگذارید. اگر دیسک دائمی ندارید، با هر دیپلوی/ری‌استارت اطلاعات پاک می‌شود.
5. لاگ اولین اجرا را ببینید (رمز موقت مالک آنجا چاپ می‌شود).
6. `better-sqlite3` همراه خودش باینری آماده برای لینوکس/ویندوز/مک دارد و فایل `.npmrc` پروژه جلوی کامپایل غیرضروری را می‌گیرد، پس نیازی به g++ یا اینترنت بین‌الملل هنگام نصب نیست. اگر هنوز موقع اجرا خطای بارگذاری ماژول دیدید، نسخه Node میزبان را ۲۰ یا ۲۲ انتخاب کنید یا از پشتیبانی بخواهید معماری سرور (x64/arm64) را بگویند.

## پشتیبان‌گیری و بازیابی

- **خودکار:** هر ۲۴ ساعت یک نسخه کامل SQLite در `DATA_DIR/backups` ساخته می‌شود (۷ نسخه آخر).
- **دستی:** پنل ← پشتیبان‌گیری ← «دانلود نسخه پشتیبان». این را روزانه/هفتگی روی کامپیوتر خودتان نگه دارید؛ پشتیبانی که روی همان سرور است با از دست رفتن سرور از بین می‌رود.
- **بازیابی:** همان صفحه، آپلود فایل `.sqlite`. فایل اعتبارسنجی می‌شود و قبل از جایگزینی، از وضعیت فعلی یک نسخه `before-restore` ساخته می‌شود.
- **تصاویر محصولات** در `DATA_DIR/uploads` هستند و داخل فایل SQLite نیستند؛ هنگام انتقال سرور آن پوشه را هم کپی کنید.

## کار در شرایط اینترنت ملی

آنچه برنامه خودش در اختیار دارد و بدون اینترنت بین‌الملل کار می‌کند:
- کل سایت، دیتابیس، فونت، تصاویر و پنل مدیریت از همان سرور داخلی سرو می‌شوند؛ هیچ CDN یا فونت خارجی استفاده نشده است.
- ورود اصلی با **موبایل و رمز عبور** است و به گوگل وابسته نیست. اگر گوگل در دسترس نباشد، دکمه آن پیام توضیحی نشان می‌دهد و بقیه سایت کار می‌کند.
- پنل مدیریت هر ۲۵ ثانیه سفارش جدید را بررسی می‌کند و اعلان و صدا می‌دهد.
- مرور فروشگاه با سرویس‌ورکر در ضعف شبکه کاربر هم تا حدی کار می‌کند (داده‌های خصوصی کش نمی‌شوند).

آنچه به شبکه یا سرویس بیرونی وابسته است و برنامه نمی‌تواند تضمین کند:
- **ورود با گوگل:** سرور برای تأیید توکن به `oauth2.googleapis.com` وصل می‌شود و مرورگر کاربر هم باید به گوگل برسد.
- **درگاه پرداخت:** در این نسخه درگاه آنلاین وصل نیست؛ پرداخت پس از تأیید سفارش با هماهنگی (مثلاً کارت‌به‌کارت) انجام می‌شود. متن راهنما از تنظیمات قابل ویرایش است.

## امنیت

رمزها با bcrypt هش می‌شوند • نشست‌ها با توکن تصادفی در کوکی HttpOnly/SameSite (فقط هش آن در دیتابیس) • هدر سفارشی برای همه درخواست‌های تغییردهنده (دفاع CSRF) • محدودیت تعداد تلاش برای ورود، ثبت سفارش و پیگیری • قیمت و جمع سفارش فقط سمت سرور محاسبه می‌شود و موجودی در یک تراکنش کم می‌شود (جلوگیری از فروش بیش از موجودی) • آپلود فقط JPG/PNG/WebP با بررسی امضای فایل • CSP و هدرهای helmet • پیگیری عمومی آدرس مشتری را نشان نمی‌دهد • فقط مالک به پشتیبان‌گیری و مدیریت نقش‌ها دسترسی دارد.

## ساختار پروژه

```
server.js   API و سرو فایل‌ها        orders.js  ثبت سفارش و چرخه وضعیت
db.js       SQLite و schema          util.js    ابزارها
test.js     تست‌ها
public/     app.js (فروشگاه)  admin.js (پنل)  style.css  sw.js  img/  fonts/
```

برای افزودن قابلیت جدید: جدول را در `db.js` (با `CREATE TABLE IF NOT EXISTS`) اضافه کنید، مسیر API را در `server.js`، و صفحه را با `route(...)` در `app.js` یا یک بخش در `admin.js`.

چرخه وضعیت سفارش: `در انتظار بررسی ← تأیید ← آماده‌سازی ← ارسال ← تحویل` و در صورت لزوم «رد/لغو» (که موجودی را برمی‌گرداند).
